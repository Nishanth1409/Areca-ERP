Features

Built for the work, not for a demo

Every module exists because the books needed it — workers, wages, loans, and cash movement that has to reconcile at the end of the day.

Employees and attendance

Track workers by status — working, with loan, or other — and mark attendance against common or custom day wages.

Loans and repayments

Issue a loan, record repayments, and let the business ledger update itself instead of maintaining two sets of numbers.

Income and expenses

Record daily cash movement with category charts and a recent-activity feed on the dashboard.

PDF reports

Generate employee and finance reports you can print, hand over, or archive as a backup.

Role-based sign-in

Email or phone login with JWT sessions, so staff only reach the parts of the system they need.

Phone, laptop, television

One responsive layout across all three, plus a Capacitor configuration for building an Android APK.

Install

Self-host it in four steps

Bring your own Firebase project and JWT secret. There is no shared instance, because these are real business books.

1

Clone and install

Node 20 or newer is recommended for Next.js 16.

git clone https://github.com/Nishanth1409/Areca-ERP.git
cd Areca-ERP
npm install
2

Configure the environment

Copy the example file, then fill in the Firebase web configuration, a service account, and a strong JWT secret. Keep the newline escapes in the private key.

cp .env.example .env
# FIREBASE_PROJECT_ID, FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY, JWT_SECRET
3

Start the app

Enable Firestore and Storage in your Firebase project first, then run the development server.

npm run dev
# http://localhost:3000
4

Create the first admin

Use Bootstrap Admin on the home page once. Change the seeded values in the bootstrap route before any real deployment — it returns 409 once an admin exists.

curl -X POST http://localhost:3000/api/bootstrap

FAQ

Good to know

Is there a public demo I can sign into?

No, and that is deliberate. This runs real business books, so you self-host it with your own Firebase project and your own admin account.

Do I need Firebase, or can I use another database?

As shipped it uses Cloud Firestore through the Firebase Admin SDK. Swapping the data layer means rewriting the server-side queries.

Can it work without a connection?

Partly. Writes are queued and there is a manual sync plus a JSON backup export, which covers a patchy connection at the farm.

How do I get the Android app?

Build the web app, then add and sync the Android platform with Capacitor and build the APK from Android Studio.
